# Players: current state

What exists in the code, one bullet per AP. Update it when an AP changes this area (projektplan §2.4).

- Players (AP 2.4): `players/domain` (profile with `seedKey` as `number[]`, list entry, limits, defaults and presets of PS US-SP-01, `livingCostsExceedIncome`, `matchingPreset`, `isOutdated` against `SIM_VERSION`/`SCHEMA_VERSION`); `PlayersService` (`players/data-access`: list from the `players`, `runtime` and `snapshots` stores, create, rename, delete under the Web Lock with `PlayersServiceError` codes, `changes$` from other tabs, `get/setLastPlayerId`, `requestPersistence` (not a pending task, requested by `requestPersistence$` without blocking: Firefox answers only after its prompt), `suggestSeed`; storage work runs as `PendingTasks`; platform ports with root defaults, fakes via `providePlayersTestPorts()` in `players/data-access/testing`); Signal-Forms schemas in `players/ui/schemas` (`playerNameSchema`, `newPlayerSchema`, `amountRangeSchema`); app-wide players slice `players/feature/state` (`PlayersFacade`; enter guards `enterPlayersPage`/`leavePlayersPage`/`enterNewPlayerPage`; rename dialog `players/feature/dialog-rename-player` and delete confirmation opened from effects); pages „Spielerauswahl“ (`players/ui/player-list`) and „Spieler anlegen“ (`players/ui/form-new-player`); opening or creating a player remembers it and navigates to `/game/:id` (loading it in the worker follows in AP 2.5).
- Export and import (AP 6.1, TS §9.1, §9.3, §10): format version 1 in `players/domain` (`models/player-export.model.ts`: `PlayerExport`, `EXPORT_FORMAT_VERSION`, `IMPORT_ERRORS`; `player-export-logic.ts`: `buildPlayerExport`, `exportFileName`, `encodePlayerExport`, `decodePlayerExport`; guards `player-export.utils.ts`; `player-import-logic.ts`: `importedGame`, `importedPlayerName`; frozen fixture `testing/export-v1.ts`, regenerated before 1.0 with `UPDATE_EXPORT_FIXTURE=1`). `PlayersService` (injects the `EngineService`): `importPlayer(content, suffix)` (worker first, then the profile; deletes the worker records if the profile fails), `importProgress$`, `exportPlayer(name)`, `pgo.backup` (`loadBackup`, `recordExport`, `setBackupInterval`, `remindBackup`; deleting a player removes its entry). Backup rules in `backup-logic.ts` (`backupReminderDue`, `parseBackupSettings`; `models/backup.model.ts`). The app-wide slice handles import (dialog `feature/dialog-import-player` from `importPlayer$`, file or text, progress `importRatio$`, success like creating a player, toasts per error code and for a different market checksum), export (`exportPlayer$` with ID and name from the session slice, dialog `feature/dialog-export-player` with download through `FILE_DOWNLOAD` and CDK `Clipboard`; contents never pass the store), `backup$` (loaded on `SessionActions.enterGame`) and the reminder toast after `loadPlayerSuccess` (`remindBackup$`). UI: „Spielstand importieren“ (`players.list.import`) on the player list, `players/ui/player-backup` on the settings page.
- Settings page (AP 6.2): `clickedRenameOpenPlayer` renames the player of the open game (ID and name from the `session` slice, same dialog via `#renameDialog`); `renamePlayerSuccess` also updates `session.playerName`. `copiedSeed({ copied })` shows „Kopiert: Der Seed ist in der Zwischenablage.“ or an error (`showSeedCopied$`). `remindBackup$` reads `NOTIFICATION_CHANNEL_SETTINGS` and skips the reminder while the `backup-reminder` toast is off.
