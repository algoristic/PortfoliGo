# Notifications: current state

What exists in the code, one bullet per AP. Update it when an AP changes this area (projektplan §2.4).

- Notifications (AP 3.6, TS §3.6, §8.3, §11.3, §12): catalogue `NOTIFICATION_CODE_INFO` (category, severity, toast/browser/auto-pause defaults) and `AUTO_PAUSE_CODES` in `notifications/domain`; the engine creates them (`engine/domain/notification-system.ts`), the host stores the newest 1.000, pauses at the tick of a code with auto-pause only while visible (live or jumping, never while catching up) and sends `notification` and `report` (absence report after a catch-up or a hidden period, only when something was booked or notified). `EngineService`: `notification$`, `report$`, `setAutoPause`, `markNotificationsRead({ upTo?, seqs? })`, `notifications({ category?, offset, limit })`, `absenceReport()`; `projection.notifications` (`lastSeq`, `unread`, `autoPause`) and `clock.autoPause` (`{ seq, code }`). Slice `notifications` (`provideNotificationsState()` in `provideGameState()`; `NotificationsFacade`: `unread$`, `hasUnread$`, `autoPause$`, `category$`, `centerWindow$`, `accountNames$`) takes the projection part from `BankingActions.receivedProjection`; toasts only for codes with a toast default, bundled per code within `TOAST_BUNDLE_WINDOW_MS` (1 s real time, a `PendingTask`; `bundleNotifications`); centre page with guards `enterNotificationsPage`/`leaveNotificationsPage`, category filter, pages of 50, mark one/all read; `AbsenceReportEffects` opens `notifications/feature/dialog-absence-report` once the status is `ready` (event, or `absenceReport()` after loading), each period once. Texts in `notifications/ui/labels` (`notificationCodeLabel`, `notificationText`, category and severity labels); `notifications/ui`: `notification-list`, `notification-filter`, `absence-report`. Header bell with unread badge and `aria-label` with the number; clock bar „Pausiert: <reason>“ (`ClockFacade.autoPause$`, input `autoPauseCode` of `clock-controls`); settings section „Automatisch pausieren“ (`settings/ui/auto-pause-settings`, switches per code grouped by category). Page test `notifications.page.spec.ts` (overdrawn players of the mini world: start capital 0; the bank run on 01.04.2030 06:00), system test `e2e/notifications.e2e.ts` with `notifications.po.ts` (`createPlayerWith` for start conditions).
- Order notifications (AP 5.1c, TS §12): `notificationText(notification, accountNames, instrumentNames?)` words `order-executed` (shares with the decimals the millionths need, price with `priceDecimals`, total), `order-rejected` (reason from `orderRejectionLabel`) and `order-expired`; instrument names from the market master data (`selectInstrumentNames`, facade `instrumentNames$`, input `instrumentNames` of `notification-list` and `absence-report`, dialog data `instrumentNames`), unknown ones show their ID. The protocol guard checks the order parameters. The absence report lists executed and expired orders (`orders`, `orderCount`, the newest `MAX_REPORT_ORDERS` = 50, `REPORT_ORDER_CODES`; rejected ones are warnings) in the section „Orders (n)“ (`notifications.absence-report.order`, `.order-count`, `.order-text`).
- Payout notifications (AP 5.2, TS §12): `dividend-received` with `DividendReceivedParams` (`kind`, `accountId`, `depotId`, `instrumentId`, `quantity`, `amount`, `tax`; `tax-refund` too when `tax` < 0) from the event `distribution-paid`; guard in `engine-service.utils.ts`; texts „Dividende erhalten“/„Ausschüttung erhalten“ with amount, shares, instrument and account, plus withheld or refunded tax.
- Sale taxes in notifications (AP 5.3, TS §7.7, §12): `OrderExecutedParams.tax` (tax of a sale, refunds negative, 0 for purchases; guard checks it); a sale with a refund also creates `tax-refund` on the depot's clearing account; texts `orderExecutedSellWithTax` („…, davon … Steuer einbehalten.“) and `orderExecutedSellWithRefund` („…, dazu … Steuer erstattet.“).
- Standing order notifications (AP 5.6a, TS §12): code `standing-order-failed` (category `account`, warning, toast and browser on, auto-pause off) with `StandingOrderFailedParams` (`standingOrderId`, `fromAccountId`, `toAccountId`, `amount`, `available`) from the engine event of the same name; guard in `engine-service.utils.ts`; label „Dauerauftrag nicht ausgeführt“, text „<Betrag> von <Konto> an <Konto> wurden nicht überwiesen: verfügbar waren nur <Betrag>.“. It is a warning, so the absence report lists it.
- Savings plan notifications (AP 5.6b, TS §7.8, §12): `savings-plan-executed` (`SavingsPlanExecutedParams`: `savingsPlanId`, `depotId`, `instrumentId`, `amount`, `quantity`, `price`, `total`) and `savings-plan-failed` (`SavingsPlanFailedParams`: same IDs and `amount`, `reason` from `SAVINGS_PLAN_FAILURES`, `available`) from the engine events of the same names; catalogue defaults unchanged; guards in `engine-service.utils.ts`; texts „Sparplan: <Stück> Stück <Instrument> zu <Kurs> gekauft, belastet <Betrag>.“ and „Sparplan über <Betrag> für <Instrument> nicht ausgeführt: <Grund>“ (`savingsPlanFailureLabel`). `REPORT_ORDER_CODES` includes `savings-plan-executed`; the report section is „Orders und Sparpläne (n)“ (`uiNotifications-absenceReport-orderAndSavingsPlanCount`).
- Auto-pause while hidden (AP 6.7, E-35): `autoPauseApplies(mode, visible, backgroundMode)` and `shouldAutoPause(…, backgroundMode)` also pause a hidden app in `keep-speed` and `custom-speed`; in `realtime` and `pause` hidden events still only go to the absence report. The pause at the `backgroundPauseAfter` deadline has no `autoPause` cause; the clock bar shows it as a plain pause.
- Toast and browser per code (AP 6.2, TS §12): device settings in `pgo.settings.notifications` (overrides only); rules in `notifications/domain/notification-channel-logic.ts` (`hasNotificationChannel` – `backup-reminder` has no browser channel –, `notificationChannelEnabled`, `withNotificationChannel`, `effectiveNotificationChannels`, `parseNotificationChannelOverrides`; model `models/notification-channel.model.ts`). Token `NOTIFICATION_CHANNEL_SETTINGS` (`notifications/feature/state/notifications.config.ts`, root default: no overrides; `provideAppCore()` provides the settings slice). `showToasts$` filters with it on arrival and `bundleNotifications(notifications, settings, 'toast')` at the window end; `PlayersEffects.remindBackup$` skips the reminder (shown nor noted) with the `backup-reminder` toast off. Since AP 6.3 `showBrowserNotifications$` reads the browser part (below).
- Browser notifications (AP 6.3, TS §12, US-BN-04): `NOTIFICATION_PORT` (`notifications/data-access/notification-port/notification-port.ts`: `permission()`, `requestPermission()`, `notify({ title, body, tag })`; `WebNotificationPort` shows through the active service worker registration with `data.onActionClick.default` `focusLastFocusedOrOpen`, else `new Notification` with `onclick` focus); fake `FakeNotificationPort`/`provideFakeNotificationPort` (`data-access/testing`). Rule `browserNotificationApplies(code, { visible, permission, settings })` and `browserNotificationTag` (`pgo-<code>`) in `notifications/domain/browser-notification-logic.ts` (model `models/browser-notification.model.ts`). Effect `showBrowserNotifications$` in `NotificationsEffects`: on `receivedNotifications`, with `document.visibilityState` and the port's permission, one notification per code and engine event (`bundleNotifications(notifications, settings, channel)`, renamed from `bundleToastNotifications`); platform errors are dropped. Page test in `notifications.page.spec.ts` (hidden period → one browser notification, visible → none); system test `e2e/pwa-notifications.e2e.ts`.
- Full storage (AP 6.4, TS §9.5): the code `storage-quota-exceeded` stays unused – a notification could not be stored when the storage is full; the engine posts `warning` `storage-full` instead, shown as an error toast by `session.effects.ts`.
