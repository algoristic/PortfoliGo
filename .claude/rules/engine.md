# Engine and persistence: current state

What exists in the code, one bullet per AP. Update it when an AP changes this area (projektplan §2.4).

- Persistence infrastructure (AP 0.3): IndexedDB schema, migrations, `IndexedDbService` and `LocalStorageService` in `persistence/data-access`.
- Game engine (AP 2.1) in `engine/domain`: `createGameWorld` (`GameWorld`: seed key, world, `MarketContext`, exchange sessions with the series that close with them) and `GameEngine` (`start` runs the prehistory and processes `GAME_START_TICK`; `restore(world, snapshot, { monthStarts })`, `applyCommand`, `step`, `runUntil(target, shouldYield)`, `drainEvents`, `snapshot`, `monthStartsAfter`); scheduler as a binary heap ordered by tick, `TASK_ORDER` and sequence (`scheduler.ts`); events are codes (`dividend-announced`, `session-opened`, `ex-dividend`, `session-closed`, `month-ended`, `year-ended`, `background-mode-changed`); the only game command in M2 is `setBackgroundMode` (commands carry `id` and `tick` = `engine.tick`); `replayCommands` for restores. Prices through the port `PricePort` (`PriceSource` by default, factory option `prices`; engine scenarios use `TestMarket` from `engine/domain/testing`). The determinism lint rule covers `engine/domain`; fixture `miniGame()`.
- Worker host and `EngineService` (AP 2.2) in `engine/data-access`: protocol `EngineMessage` (`protocol: 1`) with the M2 commands and the events `clock`, `quotes`, `progress`, `reply`, `fatal` and `ENGINE_ERRORS` (`service/engine-service.model.ts`), type guards in `engine-service.utils.ts`; the framework-free `EngineHost` (`worker/engine-host.ts`) with ports for wall clock, loop timer, `post` and storage (`EngineStorage`, see AP 2.3), wrapped by `engine.worker.ts`. `EngineService` (one cold Observable per command, `EngineCommandError` with `code`, `clock$`, `progress$`, `fatal$`, `quotes(series)` counting subscribers per series, restart with reload, gives up after three failures at the same place or within 60 s, AP 6.4) is provided once in `provideAppCore()`; `ENGINE_WORKER_FACTORY` has a root default. Pure rules in `engine/domain`: `clock-pacing-logic` (`ClockPacer`, `effectiveSpeed`, overload), `jump-target-logic` (`jumpTargetTick`), `throttle-logic` (`Throttle`), `series-quote` (`seriesQuote`, `referenceCloseTick`). Test seam `engine/data-access/testing`: `provideInProcessEngineWorker(engine)` with an `InProcessEngine` (same host, mini world, `ManualTimeline`); replies are `PendingTasks`, the loop is not, so tests move game time with `await engine.advance(ms)`. Clock events are throttled (≤ 10/s, only on change), so page tests advance at least 200 ms after a user action before asserting the clock.
- Persistence in the worker (AP 2.3): DB version 4 (`persistence/data-access/schema`; `WORKER_STORES` belong to the worker, `JOURNAL_STORES` carry a `tick` and are discarded after the snapshot tick; `deletePlayerRecords` deletes a player in one transaction, the UI adds `players`). Storage port `EngineStorage` (`worker/engine-host.model.ts`) with `IndexedDbEngineStorage` in the worker (closes its connection on `versionchange`), `InMemoryEngineStorage` and `FaultyEngineStorage` (`testing/`) for crash tests. Write strategy in `EngineHost` (TS §9.2): game commands write-ahead with the clock; clock every 5 s and after each game day while the tick moves; snapshot (with new month starts and clock, after draining the engine events) every 30 s, when hidden, on unload, after a jump or the catch-up; failed periodic writes post one `warning` (`storage-failed`) and are retried by the next period. `loadPlayer` (payload `minTick` = last clock tick from localStorage): Web Lock (`PlayerLocks` port in `persistence/data-access/locks`, `WebPlayerLocks` in the worker, `FakePlayerLocks` in tests; `player-locked`), versions (`player-outdated`), restore or start, `discardAfter`, replay to max(clock, last command, `minTick`), snapshot, then the catch-up in batch mode (`catchUpTarget` in `engine/domain/catch-up-logic.ts`, `progress` `catch-up`). Daily candles at `session-closed` (`worker/daily-candle-source.ts`): live up to `liveHighLowMaxSpeed` (1 d/s) with high and low from the `PriceSource`, at 1 w/s and in batch mode open and close from `SupportValues` (`keepSupport`); the host buffers candles and writes them every 5 s, with each snapshot, on unload and before a third calendar year; `CandleBackfill.runSlice` fills what the stored candles miss (`NaN`), newest first, in small units with cost estimates, within `backfillShare` (10 % of the wall clock, `WorkShare` in `engine/domain/background-share-logic.ts`), `progress` `candles` (option `candleBackfillFrom`, `null` = off; off in `HostHarness` and `InProcessEngine` by default). Clock changes post their `clock` event only after the clock state is written. Versions in `engine/domain/version.ts`: a golden-master change raises `SIM_VERSION`, a change to the stored state raises `SCHEMA_VERSION` (7 since AP 6.7, TS §15); a snapshot with another version answers `player-outdated` (host test in `engine-host-persistence.spec.ts` for both versions). Test seams: `testing/host-harness.ts` (`HostHarness`, `advance`, `runUntil`), `InProcessEngine({ storage: 'indexed-db', locks })`; `src/test-setup.ts` installs `fake-indexeddb` with a fresh database per test.
- Session slice (AP 2.5; system test `e2e/game-session.e2e.ts`, J10 `engine-performance.e2e.ts`): the `session` slice (`engine/feature/state`, `SessionFacade`: `status$` as `SessionStatus` from `engine/domain`, `catchUpRatio$`, `jumpRatio$`, `warning$`), registered by `provideGameState()` (`shell/feature/state`) at the shell route (guards, overlay, visibility and `pagehide`: see `shell.md`); `engine/domain/last-tick-logic.ts` holds the `pgo.lastTick` rule.
- Market queries and subscriptions (AP 4.1, TS §8.2–§8.4): queries `instruments`, `instrumentDetails` (`unknown-instrument`), `screener` (computed in `engine/domain/market-screen.ts` over `DailyCloses`; cold ~75 ms, new market day ~11 ms, same day ~1.5 ms) and `candles` (newest `limit` candles in `[from, to]`, `to` capped at the current tick and before today's open, `hasOlder`; intraday from the minute curves, daily and weekly from the store `candles` plus unwritten days and from `SupportValues` where open or close is missing, `engine/data-access/worker/daily-candle-query.ts`, never from minute curves). Subscription topics `movers` (`subscribe` with `movers: true`; `marketMovers`: five gainers and losers, sector price indices; `moversPerSecond`) and `charts` (`[{ series, interval }]`, event `candle` with the changed newest candle and `previous` when a new one began; `candlePerSecond`). `EngineService.instruments()`, `instrumentDetails(id)`, `screener(criteria)`, `candles(request)`, `movers()` and `chartCandles(series, interval)`; `movers` and charts count subscribers like `quotes` and are resent after a worker restart.
- Instrument page queries (AP 4.5, TS §8.2, §6.5, §6.6): `InstrumentFacts` (`engine/domain/instrument-figures.ts`, one per game in the host) answers `instrumentFigures` (last price, indicative value at now with the weekend rule of `PriceSource.indicativeAt`, market cap, trailing dividend yield, volatility and beta over the 252 daily log returns up to the last market day before today against the world price index, performance 1M/1Y/5Y), `instrumentDividends` (history of the last five years, at most 40, newest first; next ex-date with the amount only once announced, ETFs never) and `instrumentComposition` (top 10, regions, sectors; shares `null`), all with `unknown-instrument` for unknown IDs. Rules in `market/domain/instrument-figures-logic.ts`, statistics `covariance`/`beta` in `analysis/domain/statistics-logic.ts`; `DailyCloses` takes `closeCount` (closes of shares and indices only, ETF closes in a second, costly instance from the first ETF query on); `trailingDividendYield` is shared with the screener (`market-screen.ts`); dividends and compositions are cached per market day. `EngineService.instrumentFigures(id)`, `instrumentDividends(id)`, `instrumentComposition(id)`. Measured: warm 0.1–0.2 ms, new market day share 3.9 ms / ETF 8.2 ms, cold share or index ~56 ms, ETF ~0.4 s (perf spec `instrument-figures.perf.spec.ts`).
- Orders through the host (AP 5.1c, TS §8.2–§8.4; details in `trading.md`): game commands `placeOrder`, `changeOrder`, `cancelOrder` (guards with `isOrderSpec`/`isOrderChange`); `LoadedGame.changedOrders`/`changedDepots` collected from `drainChangedOrders()`/`drainChangedDepots()` in `#drainEngineEvents`, sent as `projection.trading` (full after `loadPlayer`, else only the changed ones, same throttle as the accounts, before the reply). `EngineService.placeOrder`, `changeOrder`, `cancelOrder` and `trading$`. Command IDs are `u-<prefix>-<n>` with a prefix per `EngineService` instance from `ENGINE_COMMAND_ID_PREFIX` (root default: random, `randomCommandIdPrefix`; `provideInProcessEngineWorker` gives `s1`, `s2`, … per service), because the engine skips an ID it already saw in the same tick (`commandIds`) and a reload must not repeat IDs. `HostHarness` still numbers `t1`, `t2`, … per harness, so tests that reload a harness move the game time before sending new commands.
- Positions in the engine (AP 5.2, details in `trading.md` and `banking.md`): `PlayerState.pendingDistributions` and `custody`; task `distribution-payment` in `TASK_ORDER` between `day-change` and `bank-run`; event `distribution-paid`; the day change accrues the depots' end-of-day values; `GameEngine.securitiesValue()`. Host: `netWorth(player, engine.securitiesValue())` in projection, runtime and absence report; with positions a projection goes out on every new tick (`LoadedGame.valuedTick`, same throttle). Host test in `engine-host-orders.spec.ts` (net worth = balances + bid of the share).
- Taxes (AP 5.3, details in `banking.md`): `PlayerState.closedTaxYears`; the tax hook is `BankingSystem.taxCapitalIncome` (ports of `OrderSystem`/`DistributionSystem` take `kind` and `refs`); event `order-executed` carries `tax`. Host: `LoadedGame.taxYearSent`, `projection.taxes` with `full` or when the tax year object changed (`taxesProjection`); `EngineService.taxes$`. Engine budgets unchanged.
- Standing orders (AP 5.6a, details in `banking.md`): game commands `createStandingOrder` (reply `standingOrderId`), `changeStandingOrder`, `setStandingOrderPaused`, `deleteStandingOrder` (guards `isStandingOrderSpec`/`isStandingOrderId`); after each accepted one `GameEngine` replaces the one scheduled `bank-run` task (`unscheduleTasks` in `scheduler.ts`) by `nextBankRunTick(tick + 1, standingOrders)`. Host: `LoadedGame.standingOrdersSent`, `projection.standingOrders` (all `StandingOrderView`s) with `full` or when `player.standingOrders` is a new array; `EngineService.standingOrders$` (`StandingOrdersProjectionUpdate`). Event `standing-order-failed`. Engine budgets unchanged.
- Savings plans (AP 5.6b, details in `trading.md`): `SavingsPlanSystem`; task kind `savings-plan` in `TASK_ORDER` after `session-open` (at most one scheduled, replaced via `unscheduleTasks` after each accepted savings plan command and each run); game commands `createSavingsPlan` (reply `savingsPlanId`), `changeSavingsPlan`, `setSavingsPlanPaused`, `deleteSavingsPlan` (guards `isSavingsPlanSpec`/`isSavingsPlanChange`/`isSavingsPlanId`); events `savings-plan-executed`/`savings-plan-failed`. Host: `LoadedGame.savingsPlansSent`, `projection.savingsPlans` (`GameEngine.savingsPlanViews()`) with `full` or when `player.savingsPlans` is a new array; `EngineService.savingsPlans$` (`SavingsPlansProjectionUpdate`) and the four command methods. Budget: a year in batch mode with ten savings plans ~0,6 s.
- Daily series and performance (AP 5.7a, TS §3.8 step 4, §7.9, §8.2–§8.4, §9.1; rules in `trading.md`): `PlayerState.performance` (`PerformanceState`, replaced on every change); `PerformanceSystem` (`engine/domain/performance-system.ts`, `benchmarkSeries(world)` = world total return index and the exchange it closes with) takes the external flow of every booked transaction (hooked into the banking `journal` port), lets the benchmark buy at that exchange's `session-close` (price `priceAt` of the `-tr` series) and closes the previous day in `#dayChange` after the accruals (`closeDay`, securities at the day's last minute); `GameEngine.drainDailyPoints()` and `performanceFigures(securities)`. `TestMarket` prices series without entries at `UNPRICED_LEVEL` (100), so scenarios need not price the benchmark. Storage: `EngineStorage.saveDailyPoints`/`loadDailyPoints(player, fromDay, toDay)` and `SaveSnapshotOptions.dailyPoints`; the existing store `series` (no new DB version) holds one `SeriesRecord` per calendar year (`name` `performance`, `points` ascending, `tick` = end of the last day; `daily-series.utils.ts`: `pointYear`, `pointsByYear`, `mergePoints`); `discardAfter` keeps a year record's points up to the tick instead of dropping it. Host: `LoadedGame.unsavedPoints` (written with the transactions' interval and in every snapshot, like transactions), `performanceSent` (a new `player.performance` triggers a projection); every projection carries `performance`; query `performanceHistory` (`fromDay?`, `maxPoints?` 2–2.000, default 400; `points`, `resolution`, `total`, `tick`; stored plus unsaved points, `thinPoints`). `EngineService.performance$` (`PerformanceProjectionUpdate`) and `performanceHistory(request)`. Tests: `game-engine-performance.spec.ts`, host test `engine-host-performance.spec.ts` (figures after loading, query and thinning, live at 1 w/s = batch, reload from IndexedDB), storage contract (year records, snapshot, `discardAfter`). Covered by `SCHEMA_VERSION` 6 (end of M5).
- „Demnächst“ (AP 5.7b, details in `dashboard.md`): `GameEngine.upcoming(days)` over `upcomingInputs` (`engine/domain/upcoming-inputs.ts`, reads the state, runs nothing ahead); query `upcoming` (`days?` 1–28, default 14; `events`, `days`, `tick`) in `EngineHost.#query`, guard `isUpcomingQuery`, `EngineService.upcoming(days?)`. `LOCAL_STORAGE_KEYS` has `pgo.ui.firstSteps`.
- Background modes (AP 6.7, TS §3.6, §3.7; `SCHEMA_VERSION` 7): `PlayerState.backgroundMode` (`realtime`, `pause`, `keep-speed`, `custom-speed`), `backgroundSpeed` (default `1h`) and `backgroundPauseAfter` (`BACKGROUND_PAUSE_AFTER_MINUTES` 15–480 or `null`); `setBackgroundMode` takes `mode` with optional `speed`/`pauseAfter` (a missing one keeps its value), the `clock` event carries all three. Rules in `engine/domain/background-logic.ts` and `clock-pacing-logic.ts` (`ClockPacer`: `hiddenSince`, deadline tick, gaps over 5 s and `freeze` count as real time, `pauseDue`); `catchUpTarget` catches up in real time up to the deadline (from `hiddenSince`, else `lastSeenAt`) and pauses. Host: stored clock carries `hiddenSince` while hidden (also in `IndexedDbEngineStorage`), pause at the deadline live and after the catch-up, command `setFrozen` (allowed during jumps and catch-up, ignored without a player, snapshot on `freeze`; effect `reportFrozen$` in `session.effects.ts`), hidden `clock` ≤ 1/s (`hiddenClockPerSecond`) and no `quotes`/`movers`/`candle`. Host test `engine-host-background.spec.ts`.
- Export and import in the worker (AP 6.1, TS §10; rules in `players.md`): commands `exportPlayer` (`name`; reads state, market at the start of the day via `GameEngine.marketAtDayStart()`, stored and unsaved journal; writes nothing; `busy`, `player-not-loaded`, `storage-failed`) and `importPlayer` (`content`, `playerId`; own queue in the host, works without a loaded player, `worker/player-import.ts`: decode, Web Lock, history run in slices of `importSliceMs` (50 ms) with the port `yieldToEvents` (a `MessageChannel` in the worker, a resolved promise in tests), `progress` `import`, checksum comparison, one `saveSnapshot` with month starts, paused clock and journal; on errors nothing stays). `IMPORT_ERRORS` are part of `ENGINE_ERRORS`; host option `appVersion` (`package.json` in `engine.worker.ts`). `EngineService.exportPlayer(name)`, `importPlayer(content, playerId)`. New framework-free layer `persistence/util`: `canonical-json.ts`, `sha256.ts` (`crypto.subtle`), `tagged-json.ts` (maps, typed arrays, special numbers; recognises built-ins by their tag, so values of another realm work too), `text-codec.ts` (gzip with `CompressionStream`, base64).
- Session and settings page (AP 6.2): `session` keeps `playerSeed` from `enterGame` (`selectPlayerSeed`, `SessionFacade.playerSeed$`) and takes the new name from `PlayersActions.renamePlayerSuccess` of the open player.
- Robustness (AP 6.4 part 1, TS §8.5, §9.5): worker restart without losing actions: `EngineService` resends `loadPlayer` with `pendingCommandIds` (open game commands, `GAME_COMMAND_TYPES` in `engine-service.model.ts`); the host answers those found in the command log after the replay (`replayCommands(…, onApplied)`, `#restoredReplies`), the service fails the others with `worker-restarted` (not applied, may be repeated) and non-game commands with `worker-failed`; the frozen state is sent again after a restart. Give-up rule `engine/domain/worker-restart-logic.ts` (`recordWorkerFailure`/`recordWorkerProgress`: three failures at the same place – no `clock` beyond the last failure's tick – or three within `WORKER_FAILURE_WINDOW_MS` 60 s; the window ends the loop that throttled `clock` events would otherwise keep alive); wall clock through `ENGINE_SERVICE_CLOCK` (root default `Date.now`, `provideInProcessEngineWorker` gives `engine.now()`). Full storage: `isQuotaExceeded` (`persistence/util/quota.ts`, also as `cause`), `storageFailureResponse` (`engine/domain/storage-failure-logic.ts`: `retry-later`, `drop-candles`, `storage-full`); `EngineHost.#withQuotaRecovery` wraps every write (write-ahead, periodic writes, snapshot on load): on the first quota error `#dropCandles` (`clearCandles`, `candlesDropped`: no candle buffering, writing, job or consolidation until the next load) and one retry; still full → pause like the player (a jump ends) and `warning` `storage-full`. Host test `engine-host-recovery.spec.ts` (`FullStorage`), service tests in `engine.service.spec.ts` (`StallingStorage`).
- Consolidation of old daily candles (AP 6.4 part 2, TS §6.8): rule `market/domain/candle-consolidation-logic.ts` (`DAILY_CANDLE_YEARS` 20, `newestConsolidatedYear`, `weekParts`: per week and calendar year, at the first market day); weekly buckets in the store `candles` with `resolution` `1w`, `bucket` = year, slot = week of the year (`weeksInYear`, `weeklyCandleValues`, `decodeWeeklyValues`, `isCompleteCandleBucket` in `worker/daily-candles.utils.ts`). Port `EngineStorage.loadWeeklyCandles` and `consolidateCandles(player, seriesIds, year)` (one transaction: weekly buckets written, daily ones deleted only when all are complete; `consolidated`/`incomplete`/`none`); `clearCandles` drops the weekly ones too. Job `worker/candle-consolidation.ts` (`CandleConsolidation`: oldest due year, not settled, not `blocked`; settled per load also on failure), created after `CandleBackfill.plan(toDay, consolidated)` (skips consolidated years; `hasWorkIn(year)`), run by `#consolidationPass` after the candle job's pass, one year at a time, blocked while the job or the candle buffer/write has days of that year; config `dailyCandleYears`. The `candles` query reads weekly buckets for consolidated years (`loadWeeklyBuckets` in `daily-candle-query.ts`): daily blocks show one candle per week part, weekly blocks merge the parts. No new DB version (`1w` was in the key since version 3), `SCHEMA_VERSION` unchanged. Tests: `candle-consolidation-logic.spec.ts`, `daily-candles.utils.spec.ts`, `candle-consolidation.spec.ts`, `candle-backfill.spec.ts`, host test `engine-host-consolidation.spec.ts`. Measurements of AP 6.4 (budgets, background modes, import in the browser, NF-07) in TS §3.6, §9.6, §10.4, §14.3.
