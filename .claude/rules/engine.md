# Engine and persistence: current state

What exists in the code, by topic. When an AP changes this area, work the change into the matching topic instead of adding a bullet per AP (projektplan §2.4).

Domain parts of `engine/domain` live in their own files: banking, taxes, standing orders → `banking.md`; orders, positions, distributions, savings plans, performance rules → `trading.md`; `notification-system` → `notifications.md`; `upcoming-inputs` → `dashboard.md`.

## Game engine (`engine/domain`; AP 2.1, TS §3, §8)

- `createGameWorld` (`GameWorld`: seed key, world, `MarketContext`, exchange sessions with the series closing with them); `GameEngine` (`start` runs the prehistory and processes `GAME_START_TICK`; `restore(world, snapshot, { monthStarts })`, `applyCommand`, `step`, `runUntil(target, shouldYield)`, `drain*`, `snapshot`, `monthStartsAfter`, `marketAtDayStart`).
- Scheduler (`scheduler.ts`): binary heap by tick, then `TASK_ORDER` (`models/scheduled-task.model.ts`), then sequence. Singleton tasks are replaced via `unscheduleTasks`: the one `bank-run` after each accepted standing-order command (`nextBankRunTick(tick + 1, …)`), the one `savings-plan` after each savings-plan command and run.
- Events are codes (`models/engine-event.model.ts`), never texts. Game commands carry `id` and `tick` = `engine.tick`; the engine skips an ID already seen in the same tick (`commandIds`). `replayCommands(…, onApplied)` (`replay.ts`) for restores.
- Prices only through `PricePort` (default `PriceSource`, factory option `prices`). Scenario fixtures in `engine/domain/testing`: `TestMarket` (unpriced series at `UNPRICED_LEVEL` 100, so the benchmark needs no prices), `miniGame()`, `startBankingGame`/`withBooks`. The determinism lint rule covers `engine/domain`.
- Background modes (AP 6.7, TS §3.6, §3.7): `PlayerState.backgroundMode` (`realtime`, `pause`, `keep-speed`, `custom-speed`), `backgroundSpeed` (default `1h`), `backgroundPauseAfter` (`BACKGROUND_PAUSE_AFTER_MINUTES` 15–480 or `null`); `setBackgroundMode` with optional `speed`/`pauseAfter` (missing keeps the value). `background-logic.ts`; `ClockPacer` (`clock-pacing-logic.ts`): `hiddenSince`, deadline tick, gaps > 5 s and `freeze` count as real time, `pauseDue`; `catchUpTarget` (`catch-up-logic.ts`) catches up in real time to the deadline (from `hiddenSince`, else `lastSeenAt`), then pauses.
- `PerformanceSystem` (AP 5.7a, TS §7.9; rules in `trading.md`): external flow of every booked transaction via the banking `journal` port; buys the benchmark (`benchmarkSeries(world)`: world total-return index, `-tr` series) at its exchange's `session-close`; closes the previous day in `#dayChange` after the accruals.
- Other pure rules: `jump-target-logic`, `throttle-logic`, `series-quote` (`seriesQuote`, `referenceCloseTick`), `background-share-logic` (`WorkShare`), `storage-failure-logic`, `worker-restart-logic`, `last-tick-logic` (`pgo.lastTick`).
- `version.ts` (TS §15): golden-master change → raise `SIM_VERSION`; stored-state change → raise `SCHEMA_VERSION` (now 8, AP 7.3c: return convention E-43). Another version in a snapshot → `player-outdated`.
- `player-golden-master.ts` (AP 7.3c, TS §4.6, §15): `runPlayerScript(world?)` plays a fixed command script on the world of `golden-1` (savings account at the bank with the highest rate, depot at the first online broker, market buys of the first share and the first savings-plan ETF, savings plan, sale of half the share on 03.06.2030, end 01.10.2030 07:00 after interest and tax); `playerChecksum` hashes the canonical JSON of tick, results, player state, journal and daily series; `computePlayerChecksum()` under `withInexactMathTrap` against the frozen `PLAYER_CHECKSUM` (logic test, lab self-test, `e2e/determinism.e2e.ts`). Changes with any economic rule or the market: refreeze on purpose, note in the change log.

## Worker host and protocol (`engine/data-access`; AP 2.2, TS §8.2–§8.5)

- Protocol `EngineMessage` (`protocol: 1`) in `service/engine-service.model.ts`: `ENGINE_COMMAND_TYPES`, `GAME_COMMAND_TYPES` (written ahead to the command log), `ENGINE_QUERY_KINDS`, `ENGINE_EVENT_TYPES`, `PROGRESS_KINDS`, `ENGINE_WARNINGS`, `ENGINE_ERRORS` (incl. `IMPORT_ERRORS`). Every new payload gets a type guard in `engine-service.utils.ts`.
- `EngineHost` (`worker/engine-host.ts`, framework-free; ports for wall clock, loop timer, `post`, storage, locks), wrapped by `engine.worker.ts` (passes `appVersion`). Options/defaults in `engine-host.model.ts`.
- Events: `clock` ≤ 10/s and only on change (≤ 1/s while hidden, then no `quotes`/`movers`/`candle`), posted only after the clock state is written. `projection`: full after `loadPlayer` (before the reply), then only changed parts, throttled; `LoadedGame` tracks what was sent (`*Sent`, `changedOrders`/`changedDepots`, `valuedTick`: with positions one per new tick). Every projection carries `performance`; net worth = `netWorth(player, engine.securitiesValue())`. Part contents: see the owning file.
- Command IDs `u-<prefix>-<n>`, prefix per service instance from `ENGINE_COMMAND_ID_PREFIX` (root default random), so a reload never repeats IDs. `HostHarness` numbers `t1`, `t2`, … per harness: tests that reload a harness move game time before new commands.
- `setFrozen`: allowed during jumps and catch-up, ignored without a player, snapshot on `freeze`. The background deadline pauses live and after the catch-up; the stored clock carries `hiddenSince` while hidden.
- Market queries (AP 4.1, 4.5, TS §8.2–§8.4, §6.5, §6.6): `instruments`, `instrumentDetails`, `instrumentFigures`, `instrumentDividends`, `instrumentComposition` (unknown ID → `unknown-instrument`), `screener` (`market-screen.ts` over `DailyCloses`), `candles` (newest `limit` in `[from, to]`, `to` capped at now and before today's open, `hasOlder`; intraday from minute curves; daily/weekly from the `candles` store, unwritten days and `SupportValues` — never from minute curves; `worker/daily-candle-query.ts`). `InstrumentFacts` (`instrument-figures.ts`, one per game) caches per market day; rules in `market/domain/instrument-figures-logic.ts`; volatility/beta over 252 daily log returns up to the last market day before today vs. the world price index. `DailyCloses` `closeCount`: shares and indices only; ETF closes in a second, costly instance from the first ETF query on. Perf spec `instrument-figures.perf.spec.ts`.
- Subscriptions: `quotes`, topic `movers`, `charts` (`[{ series, interval }]` → `candle` with `previous` when a new candle began). Other queries: `performanceHistory` (`maxPoints` 2–2000, default 400; stored plus unsaved points, `thinPoints`), `upcoming` (`days` 1–28, default 14); banking/trading queries in their files.
- Export/import (AP 6.1, TS §10; format in `players.md`): `exportPlayer` writes nothing (state, market at day start, stored and unsaved journal; `busy`, `player-not-loaded`). `importPlayer` has its own queue and needs no loaded player (`worker/player-import.ts`: decode, Web Lock, history in slices of `importSliceMs` via port `yieldToEvents` (`MessageChannel` in the worker), `progress` `import`, checksum comparison, one `saveSnapshot`; on error nothing stays).

## EngineService (`engine/data-access/service`; AP 2.2, 6.4)

- Provided once in `provideAppCore()`; tokens with root defaults `ENGINE_WORKER_FACTORY`, `ENGINE_COMMAND_ID_PREFIX`, `ENGINE_SERVICE_CLOCK` (`Date.now`). One cold Observable per command/query, `EngineCommandError` with `code`; event streams (`clock$`, `projection$` and part streams, `warning$`, `fatal$`, …). `quotes`, `movers`, `chartCandles` count subscribers and are resent after a worker restart.
- Restart (TS §8.5): resends `loadPlayer` with `pendingCommandIds`; the host answers those found in the command log after the replay (`#restoredReplies`); the others fail with `worker-restarted` (not applied, may be repeated), non-game commands with `worker-failed`; the frozen state is resent. Gives up (`recordWorkerFailure`/`recordWorkerProgress`) after three failures at the same place (no `clock` beyond the last failure's tick) or three within `WORKER_FAILURE_WINDOW_MS` 60 s — the window ends loops that throttled `clock` events would keep alive; then `fatal` (overlay: `shell.md`).

## Persistence (AP 0.3, 2.3, 6.4; TS §9)

- `persistence/data-access`: `IndexedDbService`, `LocalStorageService` (`LOCAL_STORAGE_KEYS`, versioned entries), schema `DB_VERSION` 4 (`schema/idb-schema.ts`, `idb-migrations.ts`, frozen `db-v2.json`/`db-v3.json`; TS §9.7). `WORKER_STORES` belong to the worker; `JOURNAL_STORES` carry a `tick` and are discarded after the snapshot tick; `deletePlayerRecords` deletes a player in one transaction (the UI adds `players`). `PlayerLocks` port (`locks/`), `WebPlayerLocks` in the worker, `FakePlayerLocks`.
- `persistence/util` (framework-free): `canonical-json`, `sha256` (`crypto.subtle`), `tagged-json` (maps, typed arrays, special numbers; built-ins recognised by tag, so other realms work), `text-codec` (gzip, base64), `quota` (`isQuotaExceeded`, also via `cause`).
- Port `EngineStorage` (`worker/engine-host.model.ts`): `IndexedDbEngineStorage` (closes on `versionchange`), `InMemoryEngineStorage`, `FaultyEngineStorage` (`testing/`).
- Writes (TS §9.2): game commands write-ahead with the clock; clock every 5 s and after each game day; snapshot (with new month starts and clock, after draining engine events) every 30 s, when hidden, on unload, after a jump or catch-up. Transactions and daily points on the same interval and in every snapshot. A failed periodic write posts one `warning` `storage-failed` and is retried next period.
- `loadPlayer` (`minTick` = `pgo.lastTick`; `seedKey` = the profile's stored key, guard: four uint32 words; without it the host derives the key from `seed`, TS §4.1): Web Lock (`player-locked`), versions, restore or start, `discardAfter`, replay to max(clock, last command, `minTick`), snapshot, catch-up in batch mode. Host option `createWorld(seedKey)` (default `generateWorld`; seams pass `miniWorldOf`, `generateMiniWorld(seed)` stays for specs); the import derives the key from the file's seed.
- Daily candles at `session-closed` (`worker/daily-candle-source.ts`): high/low from the `PriceSource` only up to `liveHighLowMaxSpeed` (1 d/s), else open/close from `SupportValues`. Buffered; written every 5 s, with each snapshot, on unload, before a third calendar year. `CandleBackfill` fills missing (`NaN`) candles newest first within `backfillShare` (10 %) of the wall clock (`progress` `candles`; off by default in `HostHarness`/`InProcessEngine`).
- Consolidation (AP 6.4, TS §6.8): rule `market/domain/candle-consolidation-logic.ts` (`DAILY_CANDLE_YEARS` 20, `weekParts` per week and calendar year). Weekly buckets in `candles` with `resolution` `1w`, `bucket` = year, slot = week (`worker/daily-candles.utils.ts`). `consolidateCandles` deletes the daily ones only when all weekly buckets are complete. Job `CandleConsolidation` (`worker/candle-consolidation.ts`): oldest due year, one at a time after the backfill pass, blocked while backfill or the buffer has days of that year, settled per load even on failure. The `candles` query shows one candle per week part for consolidated years. No new DB version.
- Performance points: store `series`, one `SeriesRecord` per calendar year (`name` `performance`; `daily-series.utils.ts`); `discardAfter` trims a year record instead of dropping it.
- Full storage (TS §9.5): `#withQuotaRecovery` wraps every write; first quota error → `#dropCandles` (no candle work until the next load) and one retry; still full → pause (a jump ends) and `warning` `storage-full`.

## Session slice (`engine/feature/state`; AP 2.5, 6.2, 6.4)

- `session` slice, registered by `provideGameState()` (see `shell.md`). `SessionFacade`: `status$` (`SessionStatus`), `catchUpRatio$`, `jumpRatio$`, `warning$`, `playerName$`, `playerSeed$`, `reload()`. Guards `enterGame`/`leaveGame` (`session.guards.ts`); stored games only the engine finds outdated are sent back by `leaveOutdated$`.
- Effects also report visibility/frozen state, save `pgo.lastTick`, toast warnings (`storage-full` as error, `sessionEffects-storageFull`) and `reload$` (`document.location.reload()`). The name follows `PlayersActions.renamePlayerSuccess` of the open player.
