# Engine and persistence: current state

What exists in the code, one bullet per AP. Update it when an AP changes this area (projektplan §2.4).

- Persistence infrastructure (AP 0.3): IndexedDB schema, migrations, `IndexedDbService` and `LocalStorageService` in `persistence/data-access`.
- Game engine (AP 2.1) in `engine/domain`: `createGameWorld` (`GameWorld`: seed key, world, `MarketContext`, exchange sessions with the series that close with them) and `GameEngine` (`start` runs the prehistory and processes `GAME_START_TICK`; `restore(world, snapshot, { monthStarts })`, `applyCommand`, `step`, `runUntil(target, shouldYield)`, `drainEvents`, `snapshot`, `monthStartsAfter`); scheduler as a binary heap ordered by tick, `TASK_ORDER` and sequence (`scheduler.ts`); events are codes (`dividend-announced`, `session-opened`, `ex-dividend`, `session-closed`, `month-ended`, `year-ended`, `background-mode-changed`); the only game command in M2 is `setBackgroundMode` (commands carry `id` and `tick` = `engine.tick`); `replayCommands` for restores. Prices through the port `PricePort` (`PriceSource` by default, factory option `prices`; engine scenarios use `TestMarket` from `engine/domain/testing`). The determinism lint rule covers `engine/domain`; fixture `miniGame()`.
- Worker host and `EngineService` (AP 2.2) in `engine/data-access`: protocol `EngineMessage` (`protocol: 1`) with the M2 commands and the events `clock`, `quotes`, `progress`, `reply`, `fatal` and `ENGINE_ERRORS` (`service/engine-service.model.ts`), type guards in `engine-service.utils.ts`; the framework-free `EngineHost` (`worker/engine-host.ts`) with ports for wall clock, loop timer, `post` and storage (`EngineStorage`, see AP 2.3), wrapped by `engine.worker.ts`. `EngineService` (one cold Observable per command, `EngineCommandError` with `code`, `clock$`, `progress$`, `fatal$`, `quotes(series)` counting subscribers per series, restart with reload, gives up after three failures) is provided once in `provideAppCore()`; `ENGINE_WORKER_FACTORY` has a root default. Pure rules in `engine/domain`: `clock-pacing-logic` (`ClockPacer`, `effectiveSpeed`, overload), `jump-target-logic` (`jumpTargetTick`), `throttle-logic` (`Throttle`), `series-quote` (`seriesQuote`, `referenceCloseTick`). Test seam `engine/data-access/testing`: `provideInProcessEngineWorker(engine)` with an `InProcessEngine` (same host, mini world, `ManualTimeline`); replies are `PendingTasks`, the loop is not, so tests move game time with `await engine.advance(ms)`. Clock events are throttled (≤ 10/s, only on change), so page tests advance at least 200 ms after a user action before asserting the clock.
- Persistence in the worker (AP 2.3): DB version 4 (`persistence/data-access/schema`; `WORKER_STORES` belong to the worker, `JOURNAL_STORES` carry a `tick` and are discarded after the snapshot tick; `deletePlayerRecords` deletes a player in one transaction, the UI adds `players`). Storage port `EngineStorage` (`worker/engine-host.model.ts`) with `IndexedDbEngineStorage` in the worker (closes its connection on `versionchange`), `InMemoryEngineStorage` and `FaultyEngineStorage` (`testing/`) for crash tests. Write strategy in `EngineHost` (TS §9.2): game commands write-ahead with the clock; clock every 5 s and after each game day while the tick moves; snapshot (with new month starts and clock, after draining the engine events) every 30 s, when hidden, on unload, after a jump or the catch-up; failed periodic writes post one `warning` (`storage-failed`) and are retried by the next period. `loadPlayer` (payload `minTick` = last clock tick from localStorage): Web Lock (`PlayerLocks` port in `persistence/data-access/locks`, `WebPlayerLocks` in the worker, `FakePlayerLocks` in tests; `player-locked`), versions (`player-outdated`), restore or start, `discardAfter`, replay to max(clock, last command, `minTick`), snapshot, then the catch-up in batch mode (`catchUpTarget` in `engine/domain/catch-up-logic.ts`, `progress` `catch-up`). Daily candles at `session-closed` (`worker/daily-candle-source.ts`): live up to `liveHighLowMaxSpeed` (1 d/s) with high and low from the `PriceSource`, at 1 w/s and in batch mode open and close from `SupportValues` (`keepSupport`); the host buffers candles and writes them every 5 s, with each snapshot, on unload and before a third calendar year; `CandleBackfill.runSlice` fills what the stored candles miss (`NaN`), newest first, in small units with cost estimates, within `backfillShare` (10 % of the wall clock, `WorkShare` in `engine/domain/background-share-logic.ts`), `progress` `candles` (option `candleBackfillFrom`, `null` = off; off in `HostHarness` and `InProcessEngine` by default). Clock changes post their `clock` event only after the clock state is written. Versions in `engine/domain/version.ts`: a golden-master change raises `SIM_VERSION`. Test seams: `testing/host-harness.ts` (`HostHarness`, `advance`, `runUntil`), `InProcessEngine({ storage: 'indexed-db', locks })`; `src/test-setup.ts` installs `fake-indexeddb` with a fresh database per test.
- Session slice (AP 2.5; system test `e2e/game-session.e2e.ts`, J10 `engine-performance.e2e.ts`): the `session` slice (`engine/feature/state`, `SessionFacade`: `status$` as `SessionStatus` from `engine/domain`, `catchUpRatio$`, `jumpRatio$`, `warning$`), registered by `provideGameState()` (`shell/feature/state`) at the shell route (guards, overlay, visibility and `pagehide`: see `shell.md`); `engine/domain/last-tick-logic.ts` holds the `pgo.lastTick` rule.
- Market queries and subscriptions (AP 4.1, TS §8.2–§8.4): queries `instruments`, `instrumentDetails` (`unknown-instrument`), `screener` (computed in `engine/domain/market-screen.ts` over `DailyCloses`; cold ~75 ms, new market day ~11 ms, same day ~1.5 ms) and `candles` (newest `limit` candles in `[from, to]`, `to` capped at the current tick and before today's open, `hasOlder`; intraday from the minute curves, daily and weekly from the store `candles` plus unwritten days and from `SupportValues` where open or close is missing, `engine/data-access/worker/daily-candle-query.ts`, never from minute curves). Subscription topics `movers` (`subscribe` with `movers: true`; `marketMovers`: five gainers and losers, sector price indices; `moversPerSecond`) and `charts` (`[{ series, interval }]`, event `candle` with the changed newest candle and `previous` when a new one began; `candlePerSecond`). `EngineService.instruments()`, `instrumentDetails(id)`, `screener(criteria)`, `candles(request)`, `movers()` and `chartCandles(series, interval)`; `movers` and charts count subscribers like `quotes` and are resent after a worker restart.
