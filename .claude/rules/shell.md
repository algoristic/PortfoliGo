# Shell and bootstrap: current state

What exists in the code, one bullet per AP. Update it when an AP changes this area (projektplan §2.4).

- Bootstrap: `main.ts` boots `AppComponent` with `app.config.ts`: hash router, devtools and `provideAppCore()` from `app.providers.ts` (`PageTitleStrategy`, store, effects, router store, `LOCALE_ID` `de`, `ColorSchemeService`, `ToastService`, `EngineService`, players state, settings state and, from the settings, `CLOCK_SHORTCUTS_ENABLED`, `NOTIFICATION_CHANNEL_SETTINGS` and `VALUE_FLASH_ENABLED` (AP 6.2)), which page tests use as well. The colour scheme follows the settings: an inline script in `src/index.html` sets the `dark` and `colors-blue-orange` classes from `pgo.settings` before Angular starts, then the settings slice applies it.
- Routing and shell (AP 0.4): `''`/`**` → `/players`; the game area `/game/:playerId` (`shell/feature/shell.routes.ts`) lazy-loads the route files of the domains (TS §11.4). The player pages are real (AP 2.4); the pages of the game area are still placeholders in their target domain folders; fill them in place. Routes set `title` via `$localize`.
- Game session (AP 2.5; system tests `e2e/game-clock.e2e.ts`, `game-session.e2e.ts`, J10 `engine-performance.e2e.ts`): `provideGameState()` (`shell/feature/state`) registers the `session` slice (see `engine.md`) and the `clock` slice (see `clock.md`) once at the shell route. Guards `enterGame` (missing or outdated player → `/players` with a toast, else `loadPlayer` with `minTick` from `pgo.lastTick`) and `leaveGame`; overlay `shell/ui/session-overlay` while loading, catching up or failing (game area `inert`); visibility and `pagehide` go to the engine, `pagehide` also writes `pgo.lastTick` (`engine/domain/last-tick-logic.ts`; `deletePlayer` removes the entry). The header has two rows: the clock bar `clock/ui/clock-controls` and the market status `clock/ui/market-status` (see `clock.md`).
- Icons (Nachtrag M5): `src/assets/favicon.svg` (three rising candles on the light accent colour as a hex value; no `--` in XML comments, it makes the file invalid) and `src/assets/apple-touch-icon.png` (180 px, full-bleed, rendered once from the SVG), linked in `src/index.html` relative to `<base href="./">`; system test „icons“ in `e2e/shell.e2e.ts`. The manifest icons of AP 6.3 derive from the SVG.
- `provideGameState()` registers `provideDashboardState()` as well (AP 5.7b); the dashboard page is real (see `dashboard.md`). The header keeps the net worth from `md`; on phones the dashboard tile shows it.
- PWA bootstrap (AP 6.3, see `pwa.md`): `app.config.ts` adds `provideServiceWorker` (environment flag `serviceWorker`, only `true` in production); `provideAppCore()` adds `providePwaState()`; `AppComponent` renders `app-app-update` (update banner) after the router outlet; `src/index.html` links `manifest.webmanifest` and has a `theme-color` meta (`#0b0f14`, then `ColorSchemeService`).
- Failed session (AP 6.4, TS §8.5): when the `EngineService` gives up, the overlay `failed` (`shell/ui/session-overlay`) explains that confirmed actions are stored, shows the export hint (`shell.session-overlay.export-hint`) and „Neu laden“ (`shell.session-overlay.reload`, output `clickedReload`) → `SessionFacade.reload()` → `SessionActions.clickedReload` → effect `reload$` (`document.location.reload()`: new worker, new failure count). `storage-full` warnings show an error toast (`sessionEffects-storageFull`), other storage warnings the warning toast.
- About, glossary and command palette (AP 6.5): `provideAppCore()` provides `APP_VERSION` (`about/feature/about.config.ts`, from `package.json`). Routes `/about`, `/help` (app root) and `game/about`, `game/help` (shell routes, see `about.md`, `help.md`). The player menu (`PLAYER_MENU_ACTIONS`) has `switch-player`, `settings`, `about`, `help` (Glossar) and `export` (no longer disabled: `PlayersFacade.exportPlayer()` opens the export dialog of AP 6.1). „Suchen“ in the header (`shell.header.command-palette`; from `md` a wide button with `<kbd>Strg K</kbd>` and `aria-keyshortcuts` while the shortcuts are on, on phones an icon button) emits `clickedCommandPalette`. Command palette (PS US-UI-05, TS §11.4): `provideShellState()` now also registers `ShellEffects` (actions in `shell.actions.ts`, no reducer) and `GLOSSARY_LINK`; `shortcut$` listens for Ctrl/Cmd+K (`isCommandPaletteShortcut`, `shell/domain/command-palette-logic.ts`) while ready, without an open dialog and with `CLOCK_SHORTCUTS_ENABLED`; `openCommandPalette$` opens `shell/feature/dialog-command-palette` with `commandPaletteData(...)` (`command-palette.utils.ts`: actions, pages `PALETTE_PAGES`, speeds, switch player; instruments and „<Name> kaufen …“ only with a query) and maps the `PaletteCommand` to `selectedPaletteCommand`; `runCommand$` dispatches the clock, banking, trading and players actions, `navigate$` navigates. The dialog is an own ARIA combobox (`shell.command-palette.input`, `.list`, `.option.<id>`, `.status`, `.close`; `rankSearch` from `shared/util/search-ranking.ts`, at most 30 hits, `nextActiveIndex` with wrap-around). Page test `shell/feature/shell/command-palette.page.spec.ts`.
- Language switch (AP 6.8a, TS §11.9, E-36): `main.ts` only prepares the language — `startLanguage` (`settings/data-access/language/language-start.ts`, ports for storage, `fetch`, `loadTranslations`, `<html>`) reads `locale.language` from `pgo.settings`, loads `assets/i18n/messages.en.json` for English (missing or invalid → German with a console warning), calls `setFormatLanguage` and sets `<html lang>` — and then imports `src/bootstrap.ts` (`bootstrapApplication`) dynamically, because `$localize` in module constants runs at import. Never import app code statically into `main.ts` beyond that. `provideAppCore()` registers the locale data `de` and `en-GB` and provides `LOCALE_ID` from `formatLanguage()` (`de`/`en-GB`). The inline script of `src/index.html` sets `<html lang>` from `data.locale.language` before Angular starts (change it with `parseSettings`). The bundle script now also counts `main`'s dynamic import (the bootstrap chunk) and all static chunk imports (TS §14.3).
