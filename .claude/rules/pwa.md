# PWA: current state

What exists in the code, one bullet per AP. Update it when an AP changes this area (projektplan §2.4).

- PWA (AP 6.3, TS §13, E-05): `@angular/service-worker` 22.2.5, registered by `provideServiceWorker('ngsw-worker.js', { enabled: environment.serviceWorker, registrationStrategy: 'registerWhenStable:30000' })` in `app.config.ts` (bootstrap only; `serviceWorker` is `true` only in `environment.prod.ts`); `angular.json` builds it only in `production`. `ngsw-config.json`: group `app` prefetches `index.html`, the manifest and every `*.css`/`*.js` (all lazy chunks and both workers), group `assets` prefetches `assets/**` and `media/**/*.woff2` with `cacheQueryOptions.ignoreSearch` (Bootstrap Icons loads its font with a hash query; without it the font fails offline). Paths in `ngsw.json` are relative to the scope (`./index.html`) only because the `production` configuration sets `"baseHref": "./"`; without it the generator writes `/index.html`, and in the subfolder deployment the worker fetches the domain root's files and stops with a hash mismatch (`EXISTING_CLIENTS_ONLY`, fixed 15.11.2026). Manifest `src/manifest.webmanifest` (asset to the build root, linked in `src/index.html` with a `theme-color` meta that `ColorSchemeService` sets from `--pgo-bg`); icons `src/assets/icons/icon-192.png`, `icon-512.png`, `icon-maskable-512.png`, rendered once from `src/assets/favicon.svg` by `node scripts/render-icons.mjs` (Playwright Chromium, no image library; rerun after changing the SVG).
- Ports in `pwa/data-access/platform/platform.ts`, each with a root default: `PLATFORM_INFO` (`standalone`, `ios` via `isIosDevice`), `INSTALL_PROMPT` (`WebInstallPrompt`: keeps the last `beforeinstallprompt` without `preventDefault`, `appinstalled`), `STORAGE_ESTIMATE` (`navigator.storage.estimate()`), `APP_UPDATE` (`SwAppUpdate` over an optional `SwUpdate`: `version-ready`/`unrecoverable`, `reload(activate)`). Persistence uses `STORAGE_PERSISTENCE` of the players. Test fakes in `pwa/data-access/testing/fake-pwa-ports.ts` (`FakeInstallPrompt.offer()`, `FakeStorageEstimate`, `FakeAppUpdate.emit()`, `providePwaTestPorts`).
- Rules in `pwa/domain/pwa-logic.ts` (`installOffer` → `installed`/`prompt`/`ios-share`/`unavailable`, table in TS §13; `isIosDevice`; `storageUsageRatio`), models in `models/pwa.model.ts`.
- App-wide slice `pwa` (`providePwaState()` in `provideAppCore()`, `provideAppInitializer` dispatches `enterApp`): platform, `update` (`unrecoverable` is kept over a later `version-ready`), install availability and outcome, notification permission (read at the start and on `enterAppSettings`, requested only from the click), storage status (read on `enterAppSettings` — guard `enterAppSettings()` on the settings route — and after `clickedRequestPersistentStorage`; a `PendingTask` while loading); `PwaFacade`. Effects show a toast after `appinstalled` and on failures; `reload$` activates only a `version-ready`.
- UI: `pwa/feature/app-update` (smart, in `AppComponent`, so on every page) with `pwa/ui/update-banner` (`pwa.update`, `pwa.update.reload`, floats above the phone navigation); `pwa/ui/app-settings` (panel „App“ of the settings: `settings.app.install-status`, `.install`, `.notification-permission`, `.request-notifications`, `.storage-usage`, `.storage-ratio`, `.storage-quota`, `.storage-persisted`, `.request-persistence`); `pwa/ui/pre-release-hint` (`pwa.pre-release-hint`, players page and settings; remove it with AP 6.6).
- Tests: `pwa-logic.spec.ts`, `pwa.reducer.spec.ts`, `pwa.effects.spec.ts`; page tests in `settings.page.spec.ts` („app“ describe); system tests `e2e/pwa.e2e.ts` (manifest and icons, worker active, offline reload, settings and markets offline, a new player offline) and `e2e/pwa-notifications.e2e.ts` (Chromium only, `channel: 'chromium'`: the headless shell always denies notifications); helper `waitForServiceWorker` in `e2e/pwa.po.ts`. All other system tests run with `serviceWorkers: 'block'` (`playwright.config.ts`).
- Translations (AP 6.8a, TS §11.9, §13): `assets/i18n/messages.en.json` is in the group `assets` and is prefetched with the app; `main.ts` fetches it with `cache: 'no-cache'`. No change to `ngsw-config.json` was needed.
- Manifest per language (AP 6.8b, TS §13): `src/manifest.en.webmanifest` (`lang` `en`, English description, otherwise identical: same `id`, `start_url`, `scope`, icons, so it stays one installed app). `src/index.html` sets the `href` of `<link id="manifest">` for English; `angular.json` copies `manifest*.webmanifest`, `ngsw-config.json` prefetches both in the group `app`. `e2e/pwa.e2e.ts` checks the English link and that both manifests differ only in `lang` and `description`.
