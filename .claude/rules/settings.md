# Settings: current state

What exists in the code, one bullet per AP. Update it when an AP changes this area (projektplan §2.4).

- Settings (AP 2.6): `settings/domain` (`Settings` with one section per topic, `appearance.colorScheme` `system`/`dark`/`light`, default `dark` (E-06), `shortcuts.enabled`; `parseSettings` replaces each missing or invalid value by its default, so later sections need no new version); `SettingsService` (`settings/data-access`, `pgo.settings` version 1 via `LocalStorageService`); app-wide `settings` slice (`provideSettingsState()` in `provideAppCore()`, loaded by `provideAppInitializer` before the first route; `SettingsFacade`: `colorScheme$`, `shortcutsEnabled$`; every change is saved, failures show a toast; `applyColorScheme$` calls `ColorSchemeService.apply`). The inline script in `src/index.html` mirrors `parseSettings` for the colour scheme: change both together (TS §9.3, §11.5). The player setting „Verhalten im Hintergrund“ lives in the `clock` slice (`ClockFacade.background$`/`setBackground`, effect `setBackgroundMode$`, `requestedBackground` until a clock event confirms it; AP 6.7). Page `settings/feature/settings` with `settings/ui/device-settings` and `settings/ui/player-settings`; page test `settings.page.spec.ts` (`installSystemColorScheme` in `src/testing/color-scheme.ts` fakes `prefers-color-scheme`), system test `e2e/settings.e2e.ts`; system tests set the appearance with `storeColorScheme` (`e2e/settings.po.ts`), since the system preference alone no longer decides it.
- Background modes (AP 6.7): `settings/ui/player-settings` takes `background` (`BackgroundSettings`) and emits `selectedBackground` (`BackgroundSettingsChange`): four modes as radios, the speed select (`settings.player.background-speed`, all `SPEEDS`) only in `custom-speed`, the deadline select (`settings.player.background-pause-after`, `off` or minutes) in every mode but `pause`, and a hint on real time when closed or frozen and on battery use. The page calls `ClockFacade.setBackground`; page tests in `settings.page.spec.ts` (speed and deadline after a reload, pause at the deadline tick while hidden, `freeze`/`resume`).
- Export section (AP 6.1): the player panel ends with „Spielstand sichern“ (`players/ui/player-backup` fed by `PlayersFacade.backup$`/`exporting$`: last export on this device `settings.player.last-export`, `settings.player.export`, reminder interval `settings.player.backup-interval` for all players of the device); details in `players.md`. Page tests in `settings.page.spec.ts` (export, clipboard, round trip, reminder with a movable `PLAYERS_CLOCK`). AP 6.2 completes the page.
- Complete page (AP 6.2, TS §9.3, §11.5, §12): `Settings` has `appearance.changeColors` (`green-red`/`blue-orange`), `motion.priceHighlight` and `notifications` (`toast`/`browser` overrides per code, parsed by `parseNotificationChannelOverrides` from `notifications/domain`); `pgo.settings` stays version 1, an AP 2.6 entry gets the new defaults. Slice actions `selectedChangeColors`, `toggledPriceHighlight`, `toggledNotificationChannel`; facade `changeColors$`, `priceHighlight$`, `notificationChannels$` (overrides, fed into `NOTIFICATION_CHANNEL_SETTINGS`), `effectiveNotificationChannels$`; `applyChangeColors$` toggles `colors-blue-orange` via `ColorSchemeService.applyChangeColors` (the inline script of `src/index.html` sets it first; change both together). `provideAppCore()` also provides `VALUE_FLASH_ENABLED` (`toSignal(priceHighlight$)`) and `NOTIFICATION_CHANNEL_SETTINGS`. Page: panel „Dieses Gerät“ (`device-settings` with colours `settings.device.change-colors.*` and sample `app-price-change`, switch `settings.device.price-highlight`; `notification-channel-settings`: a table per category, switches `settings.device.notifications.<code>.toast|browser`, no browser switch for `backup-reminder`) and „Spieler“ (`player-profile`: `settings.player.name`, `.rename`, `.seed`, `.copy-seed` with `cdkCopyToClipboard`; name and seed from `SessionFacade.playerName$`/`playerSeed$`; rename and copy result through `PlayersFacade.renameOpenPlayer`/`copiedSeed`). Page tests in `settings.page.spec.ts` (complete page, colours/highlight, rename and seed, reload with stored JSON, reminder with toast off); system test „gain and loss colours“ in `e2e/settings.e2e.ts`.
- Section „App“ (AP 6.3, details in `pwa.md`): panel `settings.app` with `pwa/ui/app-settings` (installation, permission for browser notifications, storage status, hint before 1.0) fed by `PwaFacade`; the settings route has the guard `enterAppSettings()` (reads storage status and permission). Page tests in `settings.page.spec.ts` (describe „app“) replace the platform ports with `providePwaTestPorts`, `provideFakeNotificationPort` and `FakeStoragePersistence`.
- Full storage (AP 6.4, TS §9.5): a failed save of the device settings names the reason when `isQuotaExceeded(error)` (toast `settingsEffects-saveFailureStorageFull` with the export hint), otherwise the old text.
- AP 6.5: the panel „App“ ends with the disclaimer sentence `about/ui/disclaimer-hint` (`aboutLink="../about"`, `glossaryLink="../help"`). The shortcut list names „Strg/⌘ + K – Befehlspalette öffnen“; the hint (`uiSettings-deviceSettings-shortcutsHintPalette`) says that only the shortcuts without Ctrl rest while a control has the focus. The switch also turns off Ctrl/Cmd+K (`ShellEffects.shortcut$` reads `CLOCK_SHORTCUTS_ENABLED`).
- Language (AP 6.8a, PS US-UI-11, TS §9.3, §11.9): `Settings.locale.language` (`Language` `de`/`en` from `shared/util/locale.ts`, default `de`; `parseSettings`, `languageOfSettings`), still version 1. The panel „Dieses Gerät“ starts with „Sprache“ (`settings.device.language.de`/`.en`, names „Deutsch“/„English“ untranslated with `lang`, hint that the app reloads). Action `selectedLanguage` → effect `saveLanguage$` (saves, then `saveLanguageSuccess`; failure → `saveSettingsFailure` and no reload) → `reloadForLanguage$` calls `APP_RELOAD` (`shared/data-access/app-reload`; page tests use `RecordingAppReload`/`provideRecordingAppReload`). `SettingsFacade.language$`/`selectLanguage`. The language takes effect only after the reload (`main.ts`, see `shell.md`); `storedLanguage` in `language-start.ts` reads `pgo.settings` like the service. Tests: `settings-logic.spec.ts`, `language-start.spec.ts`, effects spec, page test „saves a new language and reloads the app for it“, system test `e2e/language.e2e.ts`.
