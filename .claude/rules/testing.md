# Testing: current state

What exists in the code, one bullet per AP. Update it when an AP changes this area (projektplan §2.4).

- CI repair (14.11.2026, TS §14.4): `ng test` runs isolated (`"isolate": true` in `angular.json`), because with `CI=true` the build cache is off and Vitest orders the spec files differently, so module state leaked between files of a worker. Specs with `provideMockStore` call `store.resetSelectors()` in `afterEach` (`MockStore` sets results on the module-wide selectors; this leaked `selectPhase`, `selectInstrumentsLoaded` etc. into later page tests). Check like CI with `CI=true npm run verify`; to find a leak, run `CI=true taskset -c 0 npx ng test --watch=false --isolate=false` (serial, fixed order) and pair the file that ran before the first failure with the failing file. System tests get 60 s per test in CI (`playwright.config.ts`), locally 30 s. Mutation tests use 120 s per test (`vitest.mutation.config.ts`; the dividend table of `instrument-figures.spec.ts` is slow when instrumented). `e2e/markets.e2e.ts` waits for `aria-busy="false"` on the watchlist before the reload.
