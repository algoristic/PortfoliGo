# Testing: current state

What exists in the code, by topic. When an AP changes this area, work the change into the matching topic instead of adding a bullet per AP (projektplan §2.4).

How to write tests is in `testing-guide.md`; this file lists what exists (AP 0.5; TS §14.1, §14.4).

## Helpers and infrastructure

- `src/testing/` beyond the guide: `nextFrames`, `blur` (`typeText` takes textareas); `parseGermanNumber` reads hyphen and typographic minus, `parseEuros`, `parseCompactEuros` (value and unit factor); `installScrollViewport`/`scrollTo` (CDK virtual scrolling under jsdom); `installSystemColorScheme`; `perf.ts` (`BUDGETS_MS`, `medianMs`, `expectWithinBudget`, `PERF_FACTOR`); `fast-check-setup.ts`, `logic-setup.ts`.
- Golden master: the self-test on `#/lab/simulation` computes the six checksums in the worker; `e2e/determinism.e2e.ts` compares them in every engine.
- Port doubles: `RecordingFileDownload`, `RecordingAppReload` (`shared/data-access/testing`), `providePwaTestPorts`, `provideFakeNotificationPort`; storages `StallingStorage`, `FullStorage`, `RecordingStorage`.
- CI isolation (TS §14.4): `ng test` runs isolated (`"isolate": true` in `angular.json`), because with `CI=true` the build cache is off, Vitest orders files differently and module state leaked between files. Specs with `provideMockStore` call `store.resetSelectors()` in `afterEach` (`MockStore` sets results on module-wide selectors). Check like CI with `CI=true npm run verify`; to find a leak run `CI=true taskset -c 0 npx ng test --watch=false --isolate=false` and pair the file before the first failure with the failing one.
- Timeouts: system tests 60 s per test in CI, 30 s locally (`playwright.config.ts`); mutation tests 120 s (`vitest.mutation.config.ts`; the dividend table of `instrument-figures.spec.ts` is slow instrumented).
- Engine domain specs belong to `logic`: run them with `npx vitest run`, not `ng test --include` (under jsdom the replay property of `engine-properties.spec.ts` fails on `monthStartsAfter`).
- Format language: logic specs call `setFormatLanguage('en')` inside `it` and reset in `afterEach` (module state). Page tests stay German (`provideAppCore()` reads `formatLanguage()`).
- Mutation shards: `MUTATION_SHARDS` = 8 fixed lists balanced by mutant count. Without `MUTATION_SHARD` Stryker mutates all and breaks at `BREAK_THRESHOLD` 91 % (local, `npm run verify`); with `MUTATION_SHARD=k` only list k, no break. `verify-extended.yml` runs one job per shard with its own cached `incremental.json` (saved whenever Stryker finished), then `tools/mutation-score.mjs` checks completeness and total score. A ninth shard also needs a matrix entry.

## System test infrastructure

- `e2e/serve.mjs` serves the build like the deployment, under `/portfoligo/` (`baseURL`) with another page at the root, so paths escaping the subfolder fail.
- Service workers are blocked (`serviceWorkers: 'block'`) except in `e2e/pwa.e2e.ts` and `e2e/pwa-notifications.e2e.ts` (`waitForServiceWorker` in `e2e/pwa.po.ts`, offline via `context.setOffline`). Notifications need `channel: 'chromium'` (the headless shell denies them) and `grantPermissions(['notifications'], { origin })`; a hidden tab = overriding `document.visibilityState`. WebKit runs of the PWA journeys are only checked in CI. The offline journey waits for the service worker before creating the first player (in WebKit a lazy chunk requested during the takeover got no response).
- `e2e/fixtures.ts`: the automatic fixture ignores `pageerror`s matching the option `allowedPageErrors` (default `[]`; Firefox and WebKit report uncaught worker errors as page errors, Chromium doesn't). CI containers run with `--ipc=host` (Firefox crashes with Docker's 64 MB `/dev/shm`).
- `expectAccessible` (`e2e/fixtures.ts`) waits two frames, then for running finite animations (dialog backdrop, `transition-colors`), because axe would measure intermediate colours; tests need no own waits.
- J10 budgets (`@budget`, `e2e/engine-performance.e2e.ts`) run in `npm run test:e2e` after the other tests with `--workers=1`, because parallel tests distort them.
- Page objects: `game.po.ts`, `players.po.ts`, `banking.po.ts`, `notifications.po.ts`, `settings.po.ts` (`storeLanguage`), `pwa.po.ts`.
- Page and session overlay are both `h1`; select headings by name.

## Game-area page tests (engine in process)

- Pattern (AP 2.5; `shell/feature/shell/shell.page.spec.ts`, `players/feature/new-player`): `InProcessEngine({ storage: 'indexed-db', locks })` + `provideInProcessEngineWorker(engine)` + `providePlayersTestPorts({ locks: engine.locks })`.
- Advance ≥ 200 ms after each action (clock events throttled, loop pass every 16 ms; projections throttled, so wait ~300 ms after a jump before reading the next date); read intermediate states after pausing. `config: { passBudgetMs: 0 }` makes a jump take several passes (`engine.timeline.step()`); `ManualTimeline.suspend(ms)` moves the clock without running timers (frozen process).
- The init overlay is only visible with `Router.navigateByUrl` + `detectChanges` (the harness would wait for the engine).
- „Reload“ in a page test = navigating to `/players` and back.
- Expected amounts are literal or from the public engine API (`instrumentFigures`, `instrumentDetails`, `instrumentDividends`, `EngineService.performance$`, `monthlyValues()`, `performanceHistory()`); the trading tests use a broker with 4,60 € + 2,10 € and no mark-up (checked in the test).
